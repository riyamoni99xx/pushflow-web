PushFlow API

Send web push notifications to your users from your own backend or scripts. This guide covers authentication, core endpoints, and rate limits.

Authentication

All requests must include your API key in the Authorization header. You can create and manage keys from your API keys page.

# Example request curl https://api.pushflow.dev/v1/apps \ -H "Authorization: Bearer pf_live_xxxxxxxxxxxx"

Keep your key secret — treat it like a password. Anyone with a live key can send notifications through your apps.

Quickstart

Send your first notification in three steps:

  • 1. Create an app — apps group your subscribers and notifications.
  • 2. Embed the subscribe script — add the PushFlow snippet to your site so visitors can opt in.
  • 3. Send a notification — call the send endpoint with your message.
POST /v1/apps/:appId/notifications Content-Type: application/json { "title": "New order alert", "body": "You just received a new order.", "url": "https://yourstore.com/orders/123" }
Apps
GET /v1/apps

Returns a list of all apps on your account.

POST /v1/apps

Creates a new app.

FieldTypeDescription
namestringDisplay name for the app.
websitestringSite the subscribe widget will run on.
Send notifications
POST /v1/apps/:appId/notifications

Sends a push notification to every subscriber of the given app.

FieldTypeDescription
titlestringNotification headline.
bodystringNotification body text.
urlstringLink opened when the notification is clicked.
Subscribers
GET /v1/apps/:appId/subscribers

Returns the subscriber list for an app, paginated.

DELETE /v1/apps/:appId/subscribers/:subscriberId

Removes a subscriber from an app.

Rate limits

Requests are limited per API key. Limits scale with your plan — check response headers X-RateLimit-Remaining and X-RateLimit-Reset to track usage.
